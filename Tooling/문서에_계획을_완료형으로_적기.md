## 문서에 계획을 완료형으로 적어 자기 문서에 속을 뻔했다

### 문제 배경

프로젝트 문서를 정리하다가, 여러 문서가 **아직 하지 않은 일을 완료형으로** 서술하고 있는 걸 발견했다.

### 문제

| 문서 | 기재된 내용 | 실제 |
|---|---|---|
| 로컬 실행 가이드 | "Prometheus가 Eureka에서 대상을 찾으므로 **띄우기만 하면 설정 변경 없이 자동으로 수집된다**" | `eureka_sd_configs`는 **직접 작성 필요**. `metrics_path`도 별도 지정 필요. 당시엔 Prometheus 자체가 없었음 |
| 기획서 5절 | "Prometheus·Grafana 컨테이너, 대시보드 13패널, baseline 9.03 req/s" | **환경 백지화로 전부 삭제됨** |
| 기획서 6절 | Eureka SD를 완료형으로 도식화 | 미착수 |
| 기획서 7절 | "정상 패턴 baseline ✅ 측정 완료" | 삭제됨. 재측정 필요 |

### 왜 심각한가

학습 단계의 **졸업 조건이 성립 불가능**해져 있었다 —
"이미 만들어진 대시보드의 쿼리 13개를 해석한다"인데 **그 대시보드가 없다.**

**교재가 사라진 것을 문서가 몰랐다.**

문서는 나중에 "내가 뭘 했더라"의 유일한 근거인데,
계획과 현황이 같은 시제로 섞이면 **자기 기록을 신뢰할 수 없게 된다.**

### 해결 방법

문서 전체를 실제 상태에 맞게 갱신하고, 규칙을 정했다.

| 구분 | 시제 |
|---|---|
| 계획 | **"~할 것"** |
| 현황 | **"~했다"** |

여기에 **근거 수준 표기**를 병행한다.

| 표기 | 의미 |
|---|---|
| `[확인]` | 직접 실행해서 결과를 본 것 |
| `[문서]` | 공식 문서에서 읽은 것 |
| `[미검증]` | 원리상 그럴 것이라고 추론한 것 |
| `[해석]` | 관측 결과에 대한 내 판단 |

### 배운 점

> **"했다"와 "할 것"을 섞어 적으면, 나중에 자기 문서를 못 믿는다.**
> 특히 기획서·설계서처럼 **미래를 서술하는 문서**에서 완료형을 쓰면
> 나중에 읽는 사람(대개 미래의 나)이 그걸 사실로 받아들인다.
