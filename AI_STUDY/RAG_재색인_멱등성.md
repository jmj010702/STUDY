## RAG 재색인 멱등성 — 색인을 두 번 돌리면 중복이 쌓인다

### 문제 배경

문서를 ChromaDB에 색인하는 코드를 만들고, 개발 중에 여러 번 실행했다.

### 문제

`Chroma.from_documents` / `Chroma.add_documents`는 **안 비우고 계속 추가한다.**
같은 문서를 두 번 색인하면 **같은 청크가 두 벌 저장된다.**

```
1회차 실행 → 청크 1건 저장
2회차 실행 → 같은 청크 또 저장  →  중복 1건
```

**왜 심각한가**

| | |
|---|---|
| 검색 품질 | 같은 내용이 상위 4개 중 2~3개를 차지해 다양성이 죽는다 |
| 비용 | 안 바뀐 문서를 매번 다시 임베딩한다 |
| **운영** | **배치나 재시도가 같은 색인을 여러 번 호출하면 결과가 달라진다** |

마지막이 본질이다. **멱등성(여러 번 돌려도 결과가 같음)이 없으면 운영에서 못 쓴다.**

### 시도 방법 — 세 가지를 비교했다

| 방법 | 멱등성 | 증분 | 삭제 자동청소 | 복잡도 |
|---|:---:|:---:|:---:|---|
| 비우고 재저장 | ✅ | ❌ (전체 재처리) | ✅ | 낮음 (프로토타입용) |
| **1. ID upsert** | ✅ | ✅ | ❌ 수동 | 낮음 (실무 기본) |
| **2. 인덱싱 API + RecordManager** | ✅ | ✅ | ✅ 자동 | RecordManager 필요 |

**"비우고 재저장"을 기각한 이유**: 멱등하긴 하지만 문서가 늘면 매번 전체를 다시 임베딩한다.
증분이 안 되는 순간 비용이 문서 수에 비례해서 커진다.

### 해결 방법 — 인덱싱 API + RecordManager

**RecordManager** = "무엇을 이미 색인했는지" SQLite에 기록하는 장부.
`index()`가 이 기록과 비교해 자동 처리한다.

| 상태 | 처리 |
|---|---|
| 새 청크 | **add** |
| 안 바뀜 | **skip** (재임베딩 X → 비용↓) |
| 바뀜 | **update** |
| 원본에서 사라짐 | **delete** |

```python
result = index(chunks, record_manager, vectorstore,
               cleanup="full", source_id_key="source")
# 1회차: {'num_added':1, 'num_updated':0, 'num_skipped':0, 'num_deleted':0}
# 2회차: {'num_added':0, 'num_updated':0, 'num_skipped':1, 'num_deleted':0}
```

**판단 근거**: ID upsert(방법 1)가 실무 기본이고 추가 인프라도 필요 없지만,
**삭제 동기화가 안 된다.** 원본 문서가 사라져도 벡터DB에는 남는다.
사내 규정 문서처럼 **폐지되는 문서가 있는 도메인**이라 자동 삭제가 필요하다고 판단했다.

### 검증 — 전후 비교

같은 데이터를 **두 번 색인**해서 중복 누적을 비교했다 (각 방식 임시 컬렉션, 운영 색인 무영향).

| 방식 | 2회 색인 후 중복 | 비고 |
|---|---|---|
| BEFORE: `Chroma.add_documents` (순진) | **1건** | 매 실행마다 그냥 추가 → 중복 누적 |
| AFTER: 인덱싱 API + RecordManager | **0건** | 색인 이력(sha256) 추적해 skip |

- **재색인 중복: 1건 → 0건**
- **인덱싱 API 2회차: `num_skipped=1`, 재임베딩 0회**

### 트레이드오프

**RecordManager(SQLite) 추가 인프라 비용 vs 정합성·재임베딩 비용 절감 → 정합성을 택했다.**

⚠️ 현재 청크 1개라 절대 수치는 작다. 문서가 늘면 "중복 N건 → 0건"으로 임팩트가 커진다.
**설계의 우월성은 N과 무관하지만, 수치로 말할 때는 N이 작다는 걸 같이 밝혀야 한다.**

### 겪은 오류

| 오류 | 원인 | 해결 |
|---|---|---|
| `Literal[...] 필요한데 str` | `cleanup` 타입이 너무 넓음 | `cleanup: Literal["incremental","full","scoped_full"]` |
| SHA-1 경고 | 기본 해시가 SHA-1 | 무시 가능 또는 `key_encoder="sha256"` |
| `unexpected keyword 'embeddings'` | 파라미터 오타 | `from_documents`는 `embedding=`, `Chroma()`는 `embedding_function=` |
| 파일 건너뜀(미지원 형식) | 파일에 확장자가 없음 | `연차규정` → `연차규정.txt` |
| `cp949 UnicodeDecodeError` | `requirements.txt`에 한글 주석 | 영문 주석만 사용 |

### 배운 점

> **멱등성은 운영 필수다.** 배치·재시도가 같은 색인을 여러 번 호출해도 결과가 동일해야 안전하다.
> 개발 중에는 "중복 좀 쌓이는 것"으로 보이지만, 스케줄러가 붙는 순간 성격이 바뀐다.
